# 联邦学习通信压缩：研究综述与答辩准备

这份说明解释项目做了什么、为什么改实验，以及结论的边界。
配套数据与最终准确率分析在 `results/Matched_Accuracy_Report_20260918.md`。

## 1. 要解决的实际问题

联邦学习中，客户端在本地训练，然后给服务器发送模型更新。模型参数很多，
即使不发送原始数据，上传更新也会耗费通信。

压缩的目标是：少发比特，同时让服务器得到的平均更新足够准确，不明显损害模型学习。
本项目比较 SRK 与 Fourier 型 Kashin 表示，研究准确率和通信成本之间的取舍。
目前是在一台机器上模拟联邦训练及压缩，并未实测真实网络流量、隐私保护或设备间网络延迟。

## 2. 三种核心概念

**模型更新**：客户端训练后的参数减去训练前全局参数，记为 delta。
服务器平均这些 delta，再加回全局模型。

**量化**：原来一个 float32 数需要 32 bits，改用少量离散等级表示。
1-bit 是 2 个等级；2-bit 是 4 个等级，而不是 2 个等级。
随机量化以适当概率选择相邻等级，使一个系数的平均重建值等于原系数（忽略浮点误差）。

**失真**：压缩、恢复后的更新与原更新之间的差。
相同平方误差可能出现在不同参数方向，因此失真下降不保证分类准确率等比例提高。

## 3. SRK、Fourier 和 Kashin 分别做什么

SRK 先用带随机符号的 Hadamard/FWHT 旋转，把能量分散到各坐标，再量化。
当前模型有 d=50890 个参数；FWHT 补零至 D=65536。

直接 Fourier 对照使用项目已有的随机相位 Fourier 型紧框架，把更新转换成系数后量化。
它的目的，是排除“只要换成 Fourier 就更好”的解释。

Kashin 在同一框架下进一步调整系数表示，让较大的系数不那么突出。
直觉上，相同总信息由更多、幅度较均匀的系数承担，有限量化等级更容易分配。
但系数数量增加也会增加通信，必须算总 bits。

这里的 lambda=D/d。lambda=1.288 意味着用约 1.288 倍数量的系数表示更新。
本项目使用自定义 Fourier 型框架，当前证据是数值重建和经验失真；
尚未证明该随机框架满足所有经典 Kashin 理论条件，不能宣称已得到相应最坏情形保证。

## 4. 为什么重新设计实验

| 早期问题 | 影响 | 现在怎样处理 |
|---|---|---|
| 从 10x600 改成 3x600 | 客户端数与训练数据量同时变化，准确率下降无法归因 | 固定 10x600，共 6000 张，每轮抽 3 个客户端 |
| 不同配置各用不同数据打乱顺序 | 配置差异混入训练轨迹噪声 | 新入口显式生成批次索引，所有方法重复使用 |
| 每个预算在测试集上挑最好配置 | 候选多的方法更容易偶然胜出 | 本轮预设配置，全部报告，不计算挑最大值的 frontier |
| 只比较相同量化 bit 数 | D 不同时实际通信不同 | 同时固定 D=65536 和位宽，核算端点开销 |
| 只观察最终准确率 | 看不出压缩器是否真的改善 | 先测同输入聚合失真，再做完整训练 |
| 单次运行解释很小的准确率差别 | 可能只是随机波动 | 5 个配对种子，报告每个种子差值及区间 |
| 历史图、当前图混杂 | 容易错误关联代码与结果 | 每次独立结果目录，记录版本、参数与原始数据 |

旧的实验和脚本保留，便于追溯；此次可靠比较来自新的独立入口，不能把旧图重新贴上新协议标签。

## 5. 第一阶段：把压缩器单独拿出来比较

入口：`python -m experiments.matched_distortion`。

从不压缩的参考训练第 1、5、15 轮保存真实客户端更新。所有压缩器接收同一份输入。
这样“方法 A 的输入比较容易压缩”不可能解释结果。
5 个种子，每个快照做 12 次随机量化。种子才是主要独立统计单位；
不能把同一训练轨迹下的重复量化全部当作独立训练实验。

设客户端更新为 delta_i，解压更新为 delta_hat_i，共 m 个参与者。

```text
真实平均更新 = (delta_1 + ... + delta_m) / m
接收平均更新 = (delta_hat_1 + ... + delta_hat_m) / m
聚合失真 NMSE = 两个平均更新的平方距离 / 客户端更新的平均平方长度
```

这个分母避免平均更新接近零时，相对误差因为分母太小而失控。
同时也保存了除以真实平均更新能量的另一种相对误差，以便交叉检查。

结果：相同 D、相同 bit 下，旧 Kashin 比 SRK 失真低约 18%-19%，
新 Kashin 低约 20%-22%；直接 Fourier 与 SRK 基本相当。5 个种子方向一致。
同预算下减少位宽、增加冗余的预设组合反而更差，负面结果也完整保存。

## 6. 求解器究竟改了什么

旧函数 `kashin_solve` 使用固定阈值重复裁剪并累加。
新增函数 `kashin_solve_balanced` 逐步缩小阈值，对剩余未重建部分作残差修正，
在可重建候选中保留系数范围最小者；直接 Fourier 系数也是候选。
这个选择只看输入和系数范围，不看测试准确率，也不看某一次抽样量化恰好好不好。

为什么看范围？当前量化器用最小值到最大值之间的区间分配等级，范围越大，量化步长越粗。
范围缩小有利于误差控制，但不保证每一次随机量化的误差都更小。

没有发现旧版在本次样本上严重丢失更新，旧新版未量化重建残差均很小。
新版属于算法变体，不应包装成“修复致命 bug 后才有效”。
也没有证明求得全局最优的最小无穷范数表示。

代价：本次 CPU 表示构建时间约 SRK 1.3 ms、旧 Kashin 49 ms、新 Kashin 79 ms/客户端。
这是带初始化的粗计时，不是完整通信系统性能测试。新版相对旧版仅再降约 3% 失真，
不能只展示好看的误差而不交代计算成本。

## 7. 第二阶段：完整训练验证

入口：`python -m experiments.matched_accuracy`。

- 数据：同一 MNIST 前 6000 张训练图、完整 10000 张测试图；10 个客户端，每个 600 张。
- 每轮参与 3 个客户端，所有方法使用相同参与者。
- 模型：784→64→10 的 MLP；学习率 0.05；每客户端 2 个本地 epoch；batch=32。
- 50 轮，5 个配对种子；同初始模型、训练批次、独立客户端量化随机数。
- 预设 1-bit、2-bit；每档比较 SRK、直接 Fourier、旧 Kashin、新 Kashin；另有不压缩基线。
- 编码系数数目都为 65536，lambda≈1.288；变换在一个种子内固定。
- 主指标为第 50 轮测试准确率；末 5 轮平均、交叉熵、训练准确率和聚合误差为辅助指标。
- 预设到达 85%、90%、92% 的通信量，不事后改目标来制造优势；未达标也报告。

每客户端每轮压缩通信量为 D*b+64 bits（64 是两个 float32 端点）。
总上行量为该值乘参与人数乘轮数。不压缩为 d*32 bits。
本轮同位宽的 SRK/Kashin 在同一轮已经拥有完全相同累计通信量。
不压缩基线主要用于检查精度上限，同一轮它花的通信更多，不能当作同预算精度点。

主图的阴影是跨种子的标准差，表示运行波动，不是 95% 置信区间。
最终配对准确率差值另报 t 区间（5 个种子、4 个自由度）；样本少，
没有作多重比较校正，不能凭一个偶然显著点宣称普遍优越。

## 8. 老师可能追问什么

**为什么压缩误差减少，准确率不一定增加？**

分类准确率只看最大得分对应的类别，模型输出有小变化，类别可能完全不变。
而更新平方误差给每个参数方向相同权重，学习问题对各方向的敏感度不同。
训练能补偿部分随机误差，本地训练与客户端抽样也会引入其他波动。
需要同时看损失、聚合相对误差和训练/测试表现，不能把猜测当成已证实原因。

**减少客户端为什么可能更敏感？**

在误差条件独立、均值为零时，平均误差能量是各客户端误差能量之和除以 m²。
若各客户端误差规模相近，绝对误差能量约按 1/m 下降。
这不意味着相对真实平均更新的误差必然按 1/m 下降，因为平均更新本身也会改变。
本轮固定可用数据，只改变每轮参与；它仍会影响优化，所以在同一参与方案内比较方法。

**用了共同随机数，是不是人为消除随机性？**

每次训练和量化仍然随机。只是同一 seed 下各方法遇到相同客户端、批次和随机底稿，
减少比较噪声；跨 seed 独立重跑。独立的是客户端量化流，不是强行让客户端误差互相抵消。

**为什么之前 lambda 不取 2 或 3？**

lambda≈1.288 只用于严格的机制对照：让 Kashin 与 SRK 发送完全相同的系数数目，
从而隔离表示/求解器本身的影响。它不是方法的最优 lambda，也不能作为最终方案。
你的质疑正是下一步研究问题：lambda 增大可能改善系数分布，但会发送更多系数；
若保持总通信不变，就必须降低 bit 数，量化噪声可能反而变大。

因此必须同时做两种比较：固定 bit/系数，观察 lambda 增大时的失真、准确率、通信和编码时间；
固定总通信，观察增加冗余后降 bit 是否仍有净收益。现有匹配失真结果已经包含反例：
同一 SRK payload 下提高冗余、降低 bit 的组合反而比 SRK 差。
下一步预先扫描 lambda={1.288, 2, 3, 4}，不能只挑最好点，也不能隐藏不同 lambda 的 payload。

**为什么不在测试集上选最好的配置？**

测试集应留给最终评估。方案数量越多，越容易从噪声中挑出一个看似优秀的结果。
以后若调参，应给各方法合理且可比的验证预算，用验证集选择，再独立测试。

**你证明了 Kashin 普遍优于 SRK 吗？**

没有。第一阶段证明的是在这批真实 MNIST 更新和预设预算下的经验失真优势。
第二阶段决定能否进一步声称当前任务的精度/通信优势。
自定义框架的最坏情形理论保证、不同数据集和网络结构都仍待研究。

**这算真实通信节省吗？**

目前是定长量化索引和端点的理论负载核算，没有执行真实位打包和网络传输。
下行、包头、共享随机种子建立成本暂未计入；结论必须称为上行负载比较。

**还有什么没有做？**

尚未验证真实非 IID 划分、更大模型、其他数据集、DRIVE 强基线、误差反馈、
网络实测和隐私机制。当前同一数据集测试集跨多次探索也有适应性使用的限制；
正式结论需要新的预注册实验或独立任务复核。

## 9. 三分钟汇报的主线

我研究的是联邦学习上传更新时的通信压缩。SRK 先随机旋转再量化，
Kashin 则尝试把更新表示为幅度更均匀的系数，使有限比特表达更准确。

早期实验有几个混淆因素：客户端减少时训练数据也减少，配置的随机数据顺序不完全一致，
而且从测试集挑最优结果。我们现在重新固定数据、通信预算和随机条件。

第一步使用同一批真实客户端更新，把压缩器独立拿出来比较。结果表明，同样上行数据量下，
Kashin 的平均更新失真降低约 20%，直接换 Fourier 变换没有同样收益。
但是更大冗余配更低位宽并没有胜过 SRK，说明不是冗余越大越好。

第二步把压缩放回训练，完成五个配对种子、九种配置、各 50 轮的比较。
同预算下，旧版 1-bit 最终准确率为 92.928%，SRK 为 92.784%，提高 0.144 个百分点；
新版为 92.878%，没有稳定超过旧版。达到 92% 所需通信也没有稳定减少。
所以目前能支持的是失真改善和小幅精度改善的迹象，不能宣称全面的通信优势。

补充实验在同一模型、同一真实更新上只压缩一次：首轮 1-bit 的即时精度损失
从 SRK 的约 2.14 个百分点降至新版的约 1.59 个百分点，但到第 50 轮影响都接近零。
这说明减误差是真实的，却不一定在后期变成分类准确率收益。
下一步应在预先确定的独立任务上复核旧版 1-bit，并加入强基线和计算成本，
不能靠挑选测试集最好的参数制造优势。

### 追问：旧版五个种子都更好，可以说统计显著吗？

旧版 1-bit 相对 SRK 的配对均值差为 +0.144 个百分点，未校正的 t 置信区间为
[+0.014, +0.274]。但只有五个独立种子，还比较了多个方法；两侧符号检验的
p 值为 0.0625。因此只说“值得独立复核的正向信号”，不说稳健显著或普遍成立。

### 追问：新版失真更低，为什么准确率不如旧版？

失真测量的是参数空间中的平方距离，准确率测量分类决策是否改变，两者不是一回事。
新版在旧版基础上的失真改善只有几个百分点，可能不足以改变分类结果；随机波动也存在。
我们没有测量损失曲率，不能断言某个方向的误差就是原因。实测不支持新版的额外求解成本
已经带来稳定的准确率回报，所以保留它作为消融，不把它当作必然更好的主方法。

### 追问：现在到底省没省通信？

相对未压缩，量化当然减少理论上行负载；但研究要回答的是相对 SRK 是否更省。
达到 92% 时，1-bit SRK 平均 21.2 轮，旧版和新版 Kashin 都是 21.8 轮，反而略多。
固定通信预算的精度略好与达到某个阈值的通信更少不是等价命题，必须分别报告。

# Kashin Frame Ablation Report

## Experimental Objective

This independent experiment compares a Random Fourier Frame with a Pure Gaussian Random Frame before changing the main FL pipeline. `2017.py` is not modified. Gaussian QR, Hadamard, and FWHT are not used.

## Mathematical Definition

The Fourier frame uses an arbitrary-length FFT with random phase and random signs. It does not construct a dense `d x D` matrix. The Pure Gaussian frame regenerates blocks of a fixed Gaussian matrix with entries `N(0, 1/D)` from deterministic seeds. Its scaled operator is `U=sqrt(D/d)G`, so both frames use the same Kashin convention `A=D/d`.

## Experimental Setup

The requested real model dimension is `d=50890`. The tested redundancy ratios are `lambda=1.5, 2, 3`, giving `D=76335, 101780, 152670`. Inputs are Gaussian, sparse, and a real FL update saved as `results/sample_delta.pt`. Quantization settings are 1, 2, 4, and 8 bits.

## Execution Status

The benchmark was started at the required `d=50890` using chunked Gaussian regeneration. The first Fourier/Gaussian configuration did not finish within the available runtime window and was stopped. No fabricated benchmark values are reported. The current CSV/Markdown comparison table must therefore be regenerated by completing `frame_benchmark.py` on a longer-running machine.

## Memory and Runtime Limitation

The chunked implementation avoids allocating the full `D x d` Gaussian matrix, but it does not remove the computational cost: every analysis and synthesis repeatedly evaluates Gaussian blocks, and the Kashin solver performs ten residual iterations. This is a compute-time limitation, not evidence that Gaussian QR or a smaller dimension was used.

## Recommendation

No frame is selected automatically. Fourier is expected to be the practical candidate because FFT operations are fast and support arbitrary `D`, but that is a hypothesis until the required large-scale Gaussian comparison completes.
